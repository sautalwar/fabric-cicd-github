📋 Step-by-Step Deployment Tasks

Each step shows the task, success criteria, and prerequisites for the next step.

STEP 1
Developer creates/updates a .pbix file
📝 Task
Build or modify a Power BI report in Power BI Desktop. Save as .pbix file.
✅ Success Criteria
  • A valid .pbix file exists on local disk
  • File opens correctly in Power BI Desktop
  • Data model and visuals render without errors
⚡ Prerequisites for Next Step
  • Git LFS installed locally (git lfs install)
  • Repo cloned with .gitattributes tracking *.pbix
  • Know which path to use: reports/ (Path A) or pbix-source/ (Path B)
↓
STEP 2
Push .pbix to GitHub repository
📝 Task
Copy .pbix to the appropriate folder and push:

git add reports/MyReport.pbix
git commit -m "Add MyReport"
git push origin main
✅ Success Criteria
  • File appears in GitHub repo (as LFS pointer, not raw binary)
  • Push succeeds without errors
  • GitHub Actions workflow is triggered (visible in Actions tab)
⚡ Prerequisites for Next Step
  • GitHub Actions enabled on the repo
  • Workflow file exists at correct path (.github/workflows/deploy-pbix.yml)
  • Branch matches workflow trigger (main, dev, or test)
↓
STEP 3
GitHub Actions triggers and checks out code
📝 Task
Workflow runs on ubuntu-latest. Checks out repo with lfs: true (downloads actual binary, not pointer). Determines target environment from branch name or workflow_dispatch input.
✅ Success Criteria
  • Runner starts successfully
  • Git LFS pulls the actual .pbix binary (file size > 1KB)
  • Environment correctly resolved (dev/test/prod)
⚡ Prerequisites for Next Step
  • AZURE_TENANT_ID secret must be set
  • AZURE_CLIENT_ID secret must be set
  • AZURE_CLIENT_SECRET secret must be set (valid, not expired)
↓
STEP 4
Authenticate to Microsoft Entra ID
📝 Task
POST to https://login.microsoftonline.com/{tenant}/oauth2/v2.0/token with client credentials grant.
Scope: https://analysis.windows.net/powerbi/api/.default
Receives a Bearer access token valid for ~60 minutes.
✅ Success Criteria
  • HTTP 200 response from token endpoint
  • Response contains valid access_token (starts with "ey...")
  • Token is masked in logs (::add-mask::)
⚡ Prerequisites for Next Step
  • Valid access token obtained
  • Service principal has Power BI workspace access (Admin/Member role)
  • Tenant setting "Allow service principals to use Power BI APIs" enabled
  • POWERBI_WORKSPACE_ID_{env} secret set for target environment
↓
STEP 5
Identify changed .pbix files
📝 Task
For push events: git diff --name-only HEAD~1 HEAD -- 'reports/**/*.pbix'
For workflow_dispatch: find reports/ -name "*.pbix"
Outputs a list of files to deploy.
✅ Success Criteria
  • At least one .pbix file identified (otherwise skip with warning)
  • File paths are valid and files exist on disk
  • Output list is stored for the deploy loop
⚡ Prerequisites for Next Step
  • scripts/import-pbix.sh exists and is executable
  • jq and curl available on runner (ubuntu-latest includes both)
↓
STEP 6
Upload .pbix via Power BI REST API
📝 Task
For each file, import-pbix.sh runs:

1. URL-encode display name (strip .pbix extension)
2. POST /v1.0/myorg/groups/{workspaceId}/imports?datasetDisplayName={name}&nameConflict=CreateOrOverwrite
3. Send file as multipart/form-data
4. Extract importId from response
✅ Success Criteria
  • HTTP 200/202 response from imports endpoint
  • Valid importId returned in response body
  • No "Unauthorized" or "Forbidden" errors
⚡ Prerequisites for Next Step
  • Import accepted (importId available)
  • Network connectivity to api.powerbi.com maintained
  • Token still valid (hasn't expired during upload of large file)
↓
STEP 7
Poll import status until completion
📝 Task
Every 10 seconds, call GET /groups/{workspaceId}/imports/{importId}
Check importState field. Continue until "Succeeded", "Failed", or 60 polls (10min timeout).
✅ Success Criteria
  • importState = "Succeeded"
  • Response contains datasets[0].id (Dataset ID)
  • Response contains reports[0].id (Report ID)
  • Both IDs written to GITHUB_OUTPUT for downstream use
⚡ Prerequisites for Next Step
  • All files successfully imported (zero failures)
  • If any file fails: workflow exits with code 1
↓
STEP 8
Report live in Fabric workspace
📝 Task
Deployment complete. Report and dataset are now live in the target Fabric workspace. GitHub Step Summary is written with the deployment results.
✅ Final Success Criteria
  • Report visible in Fabric workspace
  • Dataset refreshable / queryable
  • GitHub Actions workflow shows green ✅
  • Step Summary displays deployed file list with IDs
⚡ What Happens Next
  • To promote to TEST: push to test branch or use workflow_dispatch
  • To promote to PROD: use workflow_dispatch with environment: prod
  • Existing report subscriptions/bookmarks are preserved (CreateOrOverwrite)
